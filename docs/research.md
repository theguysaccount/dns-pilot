# Feasibility and foundation choices

Research date: October 1, 2026, America/New_York. The linked X post could not be read through web retrieval; its contents were not used as evidence.

## The closest existing foundation

[Namecheap's own MCP](https://www.namecheap.com/support/knowledgebase/article.aspx/10824/34/namecheap-mcp/) already supports sign-in, account domain reads, and DNS record operations. A live initialization request to `https://mcp.namecheap.com/mcp` returned HTTP 401 with an OAuth protected-resource challenge. Its discovery metadata names `https://www.namecheap.com` as authorization server. That establishes an available authenticated endpoint, not successful account access. The documentation identifies Claude as the verified client; Codex authentication and account operations require live testing.

Use it for the local plugin to avoid storing account-wide API keys. Keep only the four required Namecheap tools in `enabled_tools`. The independent product value is DNS diagnosis, record-change previews, preservation of email configuration, checkpoints, and plain-language verification. We should not claim the underlying DNS connection is new.

The project does not copy application source from either Namecheap MCP repository. The planner is purpose-built around the official remote tool contract, whose record shape, TTL range and save semantics differ from the legacy XML API. It reuses the official MCP SDK, Zod for schema validation, and tldts for registrable-domain parsing. Full dependency licenses are included in the distributed bundle.

## Legacy API fallback and hosted route

[Namecheap API access](https://www.namecheap.com/support/knowledgebase/article.aspx/9739/63/api-faq/) currently requires one of: at least 20 domains, $50 account balance, or $50 spent within the last two years; an allowlisted IPv4 is also required. A sandbox is separate. This introduces onboarding friction for a GSC Wizard-style service.

The [legacy setHosts method](https://www.namecheap.com/support/api/methods/domains-dns/set-hosts/) replaces the full host set. A direct API service must preserve all records and mail mode, implement credential isolation, rate limits, snapshots, and failure reconciliation. Do not casually wrap this endpoint in an add-record tool.

[GSC Wizard](https://www.gscwizard.com/) provides the product/distribution analogy: a third-party service connects provider data to AI workflows. Our v0.1 is a local DNS workflow integration; it is not yet that hosted SaaS business.

## OpenAI packaging research

The [plugin package guide](https://developers.openai.com/plugins/build/plugins) supports the compatibility `.codex-plugin/plugin.json` layout generated by Plugin Creator. [Submission](https://developers.openai.com/plugins/deploy/submission) requires domain verification for the MCP server and a reviewable demo account. [Authentication guidance](https://developers.openai.com/plugins/build/auth) requires OAuth 2.1 and full token validation for user-specific data and writes. No claim of eligibility, approval, or public availability is made by creating a local marketplace entry.

## Hosted implementation and live registration finding (October 2)

The hosted extension reuses [Cloudflare's Workers OAuth provider](https://github.com/cloudflare/workers-oauth-provider), pinned to 1.2.1, instead of inventing grant storage, PKCE validation, browser-bound consent or upstream-state handling. Its published implementation supplies encrypted token props, refresh/revocation semantics, and client validation. We wrap it with a narrower DNS tool allowlist and per-account Durable Objects.

Live testing showed that Namecheap's registration response does not approve our requested hosted callback. The returned redirect list contains selected AI clients; the actual authorization attempt failed. Registration is therefore not treated as completed. The provider-supported OAuth architecture is implemented but unavailable pending provider approval. The official alternate MCP Connector advertises the same OAuth resource. No workaround using another app's callback is appropriate.
